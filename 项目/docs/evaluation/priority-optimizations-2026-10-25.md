# 三项高优先级优化验收记录

日期：2026-10-25（北京时间）。范围仅为本轮搜索准备状态、比较来源覆盖和范围状态读取；未进入其他阶段。

## 实现与替换

### 统一准备状态

`documentReadiness` 同时推导当前可搜索、语义就绪、替换构建、失败或中断、图片部分能力和重试资格。汇总、搜索准备、资料详情及服务器重试检查使用同一推导。`ready` 必须具有当前片段版本的非空白片段才能显示可搜索。

旧索引仍可用而替换失败或中断时保留搜索与重试入口；图片 OCR 成功、图像解读失败时仍可单独重试未完成能力。客户端合并同一文档的在途准备请求，服务器在准备租约内再次检查。已经完成或正在处理的资料跳过，成功的图片分析结果沿用既有缓存与保留机制。

移除了以“语义数量小于总数”为重试条件的按钮判断、详情页自行解释状态的分支，以及用 POST 返回值直接替换真实索引状态的逻辑。准备结束或部分请求失败后读取服务器状态，再更新界面。

### 比较来源覆盖

明确比较、汇总和保存后的“比较全部”使用现有两路召回，在 SQL 词法召回截断前按文档轮次取候选；便携向量扫描也在固定内存预算内按文档分配候选机会。普通查找及单文档问题继续按相关性排序。每路候选仍为 20，排序候选为 15，最终证据为 7，上下文仍为 24000 字符；每次检索最多进行一次问题嵌入。

数据库在排名与截断前应用身份、工作区及文档范围。引擎在合并候选前再检查范围，取代服务层最后才过滤证据的旧逻辑。“比较全部”仅取当前身份可访问的已保存选项，并与显式选择相交。

不同文件的共享段落保留各自身份；完整文件校验和及原有片段条件匹配的副本才合并。结果区分范围数量、参与证据、回答引用、合并副本及未覆盖资料。预算不足、未就绪、无相关证据、无通过验证的引用和缺少请求事实分别展示，部分来源不会显示为完整比较。

真实样本发现“资料说明某值缺失”也可能被引用，不能据此认定请求事实完整。现有来源上下文验证调用因此增加缺失事实元数据，不增加模型调用；来源 ID 必须属于当前上下文。事实发布、数值验证、引用校验和修复次数限制保持原有门槛。

### 范围状态与共享轮询

`GET /api/index` 支持 `workspaceId`、`documentId` 或 `documentIds`，工作区与文档选择按交集处理；显式空数组返回空范围。过滤发生在分页和汇总前。全库及工作区列表采用 UUID 游标，每页最多 200 份，`summary` 是全部范围的统计，`nextCursor` 表示后续页。单文档不再依赖“最近 1500 份”。显式全库准备会遍历所有页，结束后只需读取一页及全范围汇总确认真实结果。

准备组件和详情移除了各自 4 秒、3 秒的全库 `setInterval`，改为按规范化范围共享订阅。处理中每 4 秒刷新；稳定后停止；错误按 8–30 秒退避。隐藏时暂停并取消在途读取，恢复可见、窗口恢复焦点或用户操作时刷新。包含请求超时、取消、响应代次、范围切换与卸载保护。

后台应用方案的排队任务在响应前写入现有操作日志，使慢速图片处理前的排队阶段也可见。运行时恢复跳过尚待启动的队列，原生启动恢复可将遗失任务标为中断；准备租约、索引租约和发布代次仍分别保护处理与发布。离线适配器补齐 `tryOnly` 的非阻塞语义。未新增数据库迁移或依赖。

模型、片段及图片分析版本检查按范围执行；图片检查改为一次读取与批量过期更新，清理逐图片重复读取。备份恢复与单图重试继续使用原有 POST 语义，只有普通搜索准备显式设置 `unfinishedOnly`。

生产浏览器回归还发现 Webpack 会错误改写动态 `createRequire`，造成图片 OCR 失败。改为通过 Node 原生 `getBuiltinModule` 取得加载器；中英文 OCR、生产包及单图重试均已验证。

## 边界与环境问题

- 未读取、修改或向模型发送用户原有资料；原有五份未提交文档修改未纳入本轮提交。原有数据库与原件未用于验证。
- 默认 Turbopack 在本机 PostCSS 子进程连接阶段失败；沙箱外重试相同。已用当前 Next.js 文档支持的 Webpack 完成生产构建和浏览器验收；Turbopack 本机问题未宣称解决。
- 沙箱临时目录拒绝原子 rename，因此文件与原生数据库测试在沙箱外的隔离环境执行。一次全并发测试与构建并行触发内存不足；最终以两个测试进程完成全部断言，未删除回归。
- 本轮没有调用真实 Vision 服务；图像部分成功与失败保留通过可控响应、本地真实 OCR 和浏览器重试验证。18 次真实请求只覆盖两类比较样本，不代表全面模型质量评测或大规模压力测试。
- 原子索引发布、旧索引保护、身份隔离、服务器权限检查、事实门槛及引用验证均保留。队列中断恢复依赖项目既有原生启动恢复流程；该流程和租约行为已验证。
