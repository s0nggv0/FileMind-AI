# Phase 8 frozen evaluation protocol

Production retrieval, routing, no-answer and verification code and this harness are frozen before the new corpus is created. The fixture generator is introduced afterward. No Phase 6 or Phase 7 corpus is used as input. All fixture bytes, gold queries and protocol/source hashes are published with the freeze. The first formal run is append-only; completed query rows are never replaced. Any post-run production correction requires a separate, explicitly labelled Run #2 and preserves Run #1.

This is a new synthetic corpus with code-before-data separation. The same coding agent prepares the protocol and corpus after the production freeze. It is not an external human-curated, statistically independent audit. We describe that limitation rather than claim external blindness. It must not be used to tune the frozen release.

Required sample: 90 documents, including 18 images and 9 tricky documents, and 180 queries, including at least 36 unanswerable queries. Text uses real PDF/DOCX/Markdown/TXT bytes; images use original PNG/JPG bytes. Native PDF/DOCX extraction, actual bundled OCR, configured Kimi Vision, DashScope 1024-dimensional embedding, PostgreSQL and the production retrieval/verification pipeline are used. Image analysis failures remain in the report and in the quality denominators; fixture gold is never fed into indexing, retrieval or answer generation.

Vector-only, lexical-only, always-hybrid and adaptive rankings are measured on all relevant-document questions. Rankings deduplicate documents in first-hit order. Hit@1/@5 and MRR use the first relevant document; Recall@10 uses all relevant documents, and nDCG@10 uses binary document relevance. No-answer and truly ambiguous questions have no retrieval relevance denominator. Adaptive runs the final RAG pipeline for every query, not just favourable examples. Follow-ups use the same previous-query concatenation as the HTTP Search route and retain the parent query in the record.

The answerability matrix has the six requested outcome labels plus Unavailable. Provider, citation, verifier or gold-judge outages never count as correct refusals. No-answer accuracy is correct refusals divided by all gold no-answer queries. False refusal rate is fixed insufficient-evidence responses divided by answerable/conflict queries; answerable recall is gold-correct ordinary/conflict answers over that same denominator. Released-answer coverage separately reports non-refused available answers. Ambiguous clarification has its own denominator.

Citation validity re-reads all returned citations against the current tenant database and source hash. Completeness and faithfulness report claim-weighted values from the runtime verifier on released answers, with sample/claim counts. These are post-gate automated metrics; a high result does not imply high answerable recall. All failed and rejected verification attempts are also retained, including partial/unsupported/conflicting claims. A separate frozen gold judge checks final correctness using original requested facts and original relevant documents, after generation has finished. Judge: configured `kimi-k2.6`, prompt `blind-gold-judge-v1`. The same model is used by generation, support verification and gold assessment, so correlated errors remain possible. Deterministic citation identity, quantity and source-set checks supplement it; it is not absolute factual proof.

Latency uses wall-clock milliseconds with nearest-rank P50/P95, reports sample counts, and includes failures separately. Actual query embedding plus vector scanning and adaptive retrieval are recorded independently; verified RAG includes generation, repair and support checks. The vector capacity benchmark uses explicitly synthetic 1024-dimensional vectors in the real SQL store for 100/500/1000/2000/5000 chunks. Capacity timings are not semantic quality evidence. Memory is observed process RSS/heap, not a claim that every byte belongs to vector scanning.

The Run #1 harness deliberately refuses to overwrite an existing complete or partial ledger. A disconnected infrastructure continuation requires an explicit separate continuation harness preserving completed rows, immutable parsed/image-analysis inputs and the same frozen settings; no automatic resume is implemented. A partially observed quality result cannot be discarded, reordered or hidden. Subsequent reruns require a new number and an explanation.
