# 比赛答辩问答

以下 36 个问题供答辩准备。当前源码已通过 2026-10-04 的真实主 Demo 和 12/12 检查；完整比赛提交仍需补齐视频、团队资料和新 ZIP。历史评测与最新验收分别引用对应记录。

1. **为什么不用普通文件搜索？** 文件名和关键词适合精确查找。记得概念却忘记文件名时，FileMind 可以搜索 PDF、笔记和图片中的内容，再用引用打开原件核对。
2. **为什么需要 Agent？** 一批文件导入后需要读取内容、分类、生成标签和查找关联。Agent 组合限定工具，给出组织方案，由用户审阅并决定是否 Apply。
3. **为什么使用 RAG？** 问题针对个人资料，模型的通用知识不是这批资料的证据。RAG 提供当前身份可访问的内容和来源，再生成有依据的回答。
4. **为什么 Vector 比 Hybrid 好？** Phase 6 的测试分布中，固定混合干扰了语义排序。Vector Hit@1 0.942、Hybrid 0.733 是该实验结果，不能推广成所有场景都如此。
5. **为什么还保留 Lexical？** 文件名、代码、缩写和精确词适合词法匹配。Embedding 服务故障时，本地关键词检索仍可使用。
6. **Adaptive 如何选择？** QueryAnalyzer 提取问题特征，冻结的 Router 选择向量、词法、文件名或有限的词法提升策略。Phase 9 没有再调它来适配专项问题。
7. **为什么不用 pgvector？** 当前便携 Windows PostgreSQL 环境没有启用该扩展。PortableVectorStore 使用现有 PostgreSQL 数据并进行分页线性扫描，降低部署依赖。
8. **PortableVectorStore 性能够吗？** Phase 8 测量到 5,000 chunks 的真实 SQL 容量，足以作为个人规模原型证据。线性扫描不是无限扩展方案，大型库需要另行评估。
9. **为什么 Kimi？** 当前适配器验证了 `kimi-k2.6` 的 instant mode、结构化输出、工具调用和图像能力，比赛版本沿用这一接口。首次上下文检查出现 schema 失败；后续扁平 schema 已通过真实样本和完整主 Demo。
10. **为什么 DashScope Embedding？** 向量任务与生成解耦，模型为 `qwen3.7-text-embedding-flash`、1024 维。固定模型便于缓存、版本检查与受控评价，不能随意换模型后混用旧向量。
11. **结构化输出就一定正确吗？** Schema 只检查数据形状，语义和事实仍需验证。最初六次真实调用未通过 schema，失败记录保留；后续扁平格式通过在线验收，但样本通过也不能说明所有回答都正确。
12. **Prompt Injection 怎么防？** 原文、文件名和图片说明均视为不可信数据，工具有白名单与输入验证，RAG 没有网络、shell 或删除工具。安全回归检查了已知攻击，不保证所有攻击都被阻断。
13. **图片 Prompt Injection 呢？** 图片里的指令仍只是内容。Vision 和 OCR 产物有来源标签，后续 Agent 与 RAG 沿用不可信数据边界。Phase 8 保留了实际模型攻击测量。
14. **模型幻觉怎么办？** 检索不足时拒答。生成后逐项检查引用、原子 claim、数值和事实支持，共用一次修复机会。自动评委也可能出错，用户仍需通过引用核对原文。
15. **Citation 一定正确吗？** ID、所有权、位置与版本检查能防止部分伪造、跨用户引用和过期来源。语义支持还有独立验证。有效链接不等于一句话必然正确。
16. **为何不能宣称 100% 防幻觉？** 已发布答案的条件指标、有限合成语料和自动评委不能证明所有输入都可靠。原盲测有误拒答、冲突和歧义失败。
17. **OCR 错怎么办？** 界面保留原图和 OCR 结果，方便对照。文字提取失败会显示状态，不生成缺失证据。当前不提供扫描 PDF 自动全页 OCR。
18. **图片理解错怎么办？** Vision summary 标为 AI interpretation，与 OCR 文字分开。视觉解释可能出错，点击图片来源可以核对原图。
19. **资料冲突为什么不能直接拒答？** 两个有效来源的不同值本身是可以回答的内容。结构化检查记录主题、双方来源和值，再解释分歧；没有额外依据时不替用户挑选真值。
20. **新版文件一定覆盖旧版吗？** 文件名或时间较新不证明事实更正确。只有源文本明确 supersedes 时记录该版本关系，仍保留双方引用。
21. **什么时候询问澄清？** 多个相关来源指向语义不同实体，问题又缺少关键限定时才询问。短而明确的问题、多份互补资料和要求比较全部资料不应一律澄清。
22. **澄清按钮安全吗？** 客户端提交保存的 run ID 和选项编号，服务器按当前身份读取已存选项，并限制证据文档。用户不能直接提交任意文档 ID 作为可信选择。
23. **用户数据安全吗？** PostgreSQL 的身份隔离、FORCE RLS、私有原文件存储与同源写入校验构成已测试边界。真实 AI 会发送提取文本、图片或索引文字到配置的云服务，部署仍需正确权限、HTTPS 与密钥管理。
24. **Recovery Key 安全吗？** 它是高熵 bearer credential，只保存摘要，生成/轮换时一次显示，恢复错误不泄露用户身份。拿到密钥的人可能恢复身份，因此用户必须保密。
25. **Backup 为什么不加密？** 当前格式重点是完整性、兼容性检查和可迁移恢复，没有密码加密层。产品明确提示未加密，用户应选择安全存储或使用自己管理的加密工具。
26. **为什么没有登录系统？** 当前面向单机个人资料，使用签名浏览器身份和同数据库恢复密钥。完整账号管理和 OAuth 尚未实现。
27. **和 Notion AI 有什么区别？** 本项目的具体定位是本地混合文件导入、可见 Agent 整理、原文件引用和便携恢复。没有对 Notion 当前全部能力做对照实验，因此不宣称性能或功能全面优于它。
28. **和 Obsidian 有什么区别？** FileMind 演示的是跨 PDF、DOCX、文本与图片的导入和证据问答流程。并未评测 Obsidian 的插件生态或当前 AI 扩展，不能据此做优劣排名。
29. **和网盘 AI 有什么区别？** 这里强调个人运行时、经审阅的整理、引用与恢复边界。不同网盘的实现各异，当前没有产品对照测量。
30. **设计重点是什么？** Agent 将建议与执行分开；图片索引保留 OCR、模型解释和原图；检索策略根据开发实验选择；答案发布前核对引用与事实。对应实现和实验记录可分别查看。
31. **商业模式是什么？** 当前是比赛项目，没有付费流程、商业用户或营收验证。学习和研究资料是目标使用场景，市场价值还需要实际用户验证。
32. **盲测真的独立吗？** 语料在算法冻结后生成，首次运行结果保留。语料由同一 Agent 合成，自动评委与生成使用共享模型，因此只能称为冻结后的新语料测试，不能替代外部审计或真实用户抽样。
33. **为何检索满分，回答不是满分？** 找到相关文档只是第一步。生成、语义判断、结构化输出与自动评委还可能失败。136 个问题的排名指标、127 个发布答案的 claim 指标和180个问题的服务失败不能混用分母。
34. **网络断了怎么办？** Plan B 展示已索引库、保存 Workspace、本地 OCR、Lexical、Graph、Backup 和 Recovery，并显示 Cloud AI provider unavailable。Competition Mode 不会切 Mock 冒充模型。
35. **现在可以正式提交吗？** 源码主 Demo、真实 Conflict/Ambiguity、扁平 schema 和在线 12/12 preflight 已通过。正式提交还需完成视频、团队资料、当前版本 ZIP，以及拟演示的额外问题复验；尚未做新的完整专项准确率评测。
36. **接下来做什么？** 先完成提交材料和打包，再按现场网络条件运行 preflight。发布版本保留已冻结的 Embedding、Chunk、Router 和数据库架构，新增功能另行规划。
