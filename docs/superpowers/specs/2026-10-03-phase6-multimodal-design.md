# Phase 6 implementation design

The user's Phase 6 specification authorizes two deliverables: multimodal knowledge ingestion and a harder retrieval benchmark. Existing RAG and dedicated FileMind PostgreSQL remain in place.

Images pass signature, MIME, extension, size and bounded decode validation. A server-side MultimodalPipeline coordinates independent VisionProvider and optional portable OCRProvider calls. Kimi image input is provisional until the self-created slide passes the real Gate 0. Real mode never substitutes a mock interpretation. Versioned results and separate tenant-scoped cache keys persist in multimodal_analysis; original images remain in private storage. OCR, visual interpretation and concepts become provenance-tagged knowledge sections and chunks. Failed vision can retain OCR; failed OCR can retain explicitly labelled interpretation; neither succeeding leaves a saved, unsearchable image.

The planner gains analyze_image for owned image documents. Actual processing events and provider usage feed activity. Analysis suggests organization and conservative names for human review. Shared concepts support cross-modal relationships. Authenticated source endpoints serve original bytes; Library and citation drawers show the original image before OCR and interpretation. Images never receive fabricated pages or lines. Low-density PDF detection warns about missing text; rendering fallback is implemented only if the existing parser can reliably support it.

The benchmark uses at least 60 original synthetic sources, including 12 generated images, and at least 120 fixed queries with hard negatives, multilingual paraphrases, exact symbols, multi-document evidence, ambiguous queries, follow-ups and 15–20% no-answer questions. All three retrieval variants use real embeddings and the same labels. Reports include per-type metrics, errors, evidence recall, image recall, citation validation and bounded chunk/RRF experiments. Fixtures stay outside production ranking. Configuration is not tuned to make Hybrid win.

Validation covers provider/schema errors, injection boundaries, cache/version invalidation, provenance chunks, source identity, partial failures, live image ingestion/search/RAG and browser source verification. Whole-folder copy checks image bytes, analysis, OCR and vectors, then searches the moved standalone app. Build, TypeScript, lint, unit and browser checks finish the phase. Backup/identity recovery gets a design only. Independent reviewed changes are committed and pushed without rewriting history or committing the user's existing documentation edits.
