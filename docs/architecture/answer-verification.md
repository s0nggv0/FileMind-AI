# Answer verification

Phase 8 adds a release gate after source retrieval and citation identity validation. Kimi generates bounded factual statements with separate supporting source IDs. The server attaches inline markers to each sentence unit and derives citation UUIDs from the actual supplied sources, then performs citation and fact checks. Models cannot position a citation before the wrong sentence or choose a different UUID. This formatting does not establish factual support; the semantic gate remains mandatory. No incremental answer text is sent to the browser. The browser receives progress, then only the final accepted answer. Provider failures preserve retrieval sources and expose Retry. Historical answers without a verifier result are hidden until queried again.

The verifier divides the whole answer into identified units and extracts atomic factual claims. Every unit must be covered. A second structured call checks every claim against all supplied source content, including uncited sources, and checks whether qualifiers or facts were omitted during extraction. Results contain claim, status, supporting and contradicting source IDs; hidden reasoning is never saved or displayed. The four support states are supported, partial, unsupported and conflicting. Only complete, cited support is released.

Deterministic checks bound schema, source IDs, unit/claim coverage, inline citations and common numerical equivalences. They can reject a judge-approved fabricated quantity. They do not prove all mathematical, verbal-number or date semantics. Citations are re-read from the tenant database after verification to reject sources changed while the model was running. Cancellation is checked before the final result and persistence.

All provided sources are examined for relevant disagreement. An accepted conflict answer must explicitly disclose the disagreement and cite both documents. Timestamps and version-like filenames do not prove which statement is correct; supersession needs explicit source content. Nothing deletes or silently replaces the older document.

Citation formatting and unsupported facts share a total budget of two answer generations. A first failure gets one correction. A second unsupported answer becomes the fixed insufficient-evidence response. A failed or malformed verifier call produces `answerUnavailable`, not a counted correct refusal. Completeness and faithfulness are evaluation metrics and are not shown as user percentages. Incomplete claim extraction makes both metrics unavailable rather than inflating them.

Current versions: `answer-verifier-v2`, `atomic-claims-v2`, `evidence-support-v2`. Quoted question marks stay inside the cited answer unit. List ordinals do not become factual quantities; hyphenated English and simplified/traditional Chinese time units retain their numerical meaning. An incomplete extraction gets one bounded retry, with all original units still checked independently. A factual repair receives the prior private answer and bounded failed-claim metadata. It cannot raise the total two-answer-generation budget. Extraction coverage measures the supplied answer's facts, not whether every candidate document was discussed. Compatible additional detail is not a factual conflict.

The configured Kimi model is both generator and semantic judge, so correlated model errors remain possible. These metrics are automated evaluation, not absolute truth. Explicit Mock mode uses literal extraction checks and never contributes to semantic-quality claims. Ordinary Search persists only minimal verification status and a whitelisted error code; development-only debug contains aggregates, not rejected claim text. Full claim reports are available to isolated synthetic evaluation harnesses.

Verification: 76 unit/integration tests, typecheck, lint and production build passed. The 17 offline browser tests include desktop/mobile retry, preserved sources, ignored draft events, accepted-answer refresh and no overflow. The real browser acceptance used a separate empty PostgreSQL instance and only a newly constructed QKV Markdown fixture with configured Kimi and DashScope. Fact verification, original-source match, refresh and no-answer passed; see [live result](../evaluation/phase8-rag-live-browser.json). Existing private databases and files were not used. The earlier rejected private-environment launch was replaced by this isolated harness.

The subsequent mixed Demo uncovered image-preparation revision races and incorrectly positioned model citation markers. Image preparation now shares the tenant storage lease. Three failed browser attempts and all native synthetic diagnostic attempts are retained. The final structured-statement version passed 80 unit/integration tests, clean typecheck/lint/build and the complete real mixed Demo, including QKV sources from PDF/image, original-source highlight and explicit old/new-policy supersession with both citations. See [Demo receipt](../evaluation/phase8-demo-live.json). No blind data existed while making these corrections.

Final acceptance is 81/81 unit/integration and 17/17 offline browser tests. The subsequent frozen [Blind Run #1](../evaluation/final-evaluation-summary.md) measures the limits: 8/136 answerable false refusals, 2/8 fully detected conflicts and 0/8 ambiguous clarifications. Four further conflict answers have gold-correct text and both citations but no runtime conflict record; the fixed protocol retains their failure label. Post-gate automated completeness/faithfulness is 100% on 378 released claims, which does not prove complete question handling or conflict status. One runtime structured-output failure and nine separate gold-judge failures remain counted. No release code was changed after this blind result.
